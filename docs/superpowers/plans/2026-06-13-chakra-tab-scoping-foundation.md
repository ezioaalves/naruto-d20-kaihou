# Chakra Tab Scoping Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the naruto-d20-kaihou theme stable by adopting naruto-d20-zen-theme's proven SCSS scoping architecture, then reset the chakra tab to zen's clean baseline while keeping the approved Kaihou discipline color palette.

**Architecture:** The root cause of every chakra-tab styling failure is that `scss/kaihou.scss` loads its theme partials with flat `@use` and **never wraps them in `body.naruto-zen { .naruto-zen-target { … } }`**. The partials were copied verbatim from zen-theme and still contain `&`-prefixed and bare selectors that *expect* that wrapper. Without it, Sass emits **47 literal `&…` selectors** (invalid CSS the browser silently drops — all per-sheet/per-app styling is dead) and the remaining rules compile **unscoped**, leaking globally and losing every specificity fight with PF1e's unlayered `.pf1 .xxx` rules. The fix is a single-file restructure of `kaihou.scss` to mirror zen-theme's nested `@import` scoping (verified by scratch compile: 0 `&` leaks, `.tab.chakra` → `body.naruto-zen .naruto-zen-target .tab.chakra`). With the foundation stable, we revert `_naruto-module.scss`'s chakra-tab experiments (watermarks, icon-only filter tabs, forced 5-col grid, no-top-padding) to zen's clean baseline, preserving only the Kaihou discipline colors, the 6th "kin" discipline, and the PF1e-black-`h3` background reset.

**Tech Stack:** Dart Sass (compiled to `styles/theme/zen.css` via `npm run build:css`), Vitest (`environment: node`), Foundry VTT v13 + PF1e v11.11, the `naruto-d20-kaihou` module's `scripts/theme/main.mjs` (adds `body.naruto-zen` globally + `.naruto-zen-target` to `.window-app.sheet` on render).

---

## Background facts (verified during planning)

- `scripts/theme/main.mjs` already adds `body.naruto-zen` to `<body>` (pre-`ready` via DOMContentLoaded) and `.naruto-zen-target` to `.window-app.sheet` / `.dialog` / `.compendium` / `.technique` / `.compendium-browser` on render. The DOM classes exist; only the CSS scoping is missing.
- The actor sheet matches `.window-app.sheet`, so the chakra tab (inside it) receives `.naruto-zen-target`. Scoping rules to `.naruto-zen-target .tab.chakra` *will* match.
- Sass **bubbles `@font-face` to the document root** even when `_fonts.scss` is `@import`ed inside `body.naruto-zen { … }` (confirmed in zen-theme's compiled output). So fonts stay valid.
- Kaihou partials use `@use "colors"` with namespaced `colors.$nzen-x`. A scratch compile confirmed `@use "colors"` inside an `@import`ed partial still resolves correctly.
- `tokens` and `components/index` must remain global (`:root` design tokens + theme-agnostic `.zen-card` primitives used by the wizard). They stay as top-level `@use`.
- Keep kaihou's asset paths (`../../assets/theme/imgs/…`) — they differ from zen-theme's (`../assets/imgs/…`). Do **not** copy zen's paths.

### Task 1: CSS scoping regression guard (TDD — write the test against the *current, broken* CSS first)

**Files:**
- Create: `tests/theme/css-scoping.test.mjs`

- [ ] **Step 1: Write the failing test**

```js
// tests/theme/css-scoping.test.mjs
import { readFileSync } from "node:fs";
import { fileURLToPath } from "node:url";
import { dirname, resolve } from "node:path";
import { describe, it, expect } from "vitest";

const here = dirname(fileURLToPath(import.meta.url));
const CSS_PATH = resolve(here, "../../styles/theme/zen.css");

function readCss() {
  return readFileSync(CSS_PATH, "utf8");
}

// A selector list ends at the next "{". Split the file into the selector text
// that precedes each rule block so we can inspect selectors in isolation.
function selectorTexts(css) {
  const out = [];
  const re = /([^{}]+)\{/g;
  let m;
  while ((m = re.exec(css)) !== null) {
    out.push(m[1].trim());
  }
  return out;
}

describe("compiled zen.css scoping", () => {
  it("contains no stray '&' parent selectors (those are invalid CSS the browser drops)", () => {
    const css = readCss();
    // A literal '&' followed by a class/element char means a partial's `&.foo`
    // rule was emitted without a parent — i.e. the scoping wrapper is missing.
    const leaks = [...css.matchAll(/&[a-zA-Z.#:[]/g)].map((x) => x[0]);
    expect(leaks).toEqual([]);
  });

  it("scopes every .tab.chakra rule under body.naruto-zen .naruto-zen-target", () => {
    const offenders = selectorTexts(readCss())
      .filter((sel) => sel.includes(".tab.chakra"))
      .filter((sel) =>
        // every selector in the (possibly comma-separated) list must carry the scope
        sel.split(",").some(
          (one) => one.includes(".tab.chakra") &&
            !one.includes("body.naruto-zen") &&
            !one.includes(".naruto-zen-target"),
        ),
      );
    expect(offenders).toEqual([]);
  });
});
```

- [ ] **Step 1: Replace the entry file's import block**

Replace the entire contents of `scss/kaihou.scss` with:

```scss
/**
 * naruto-d20-kaihou — top-level SCSS entry.
 *
 * Compilation target: styles/theme/zen.css (loaded by Foundry on world start;
 * effective only when body.naruto-zen class is present).
 *
 * Scoping (mirrors naruto-d20-zen-theme/scss/zen.scss):
 *   - `tokens` + `components/*` stay GLOBAL: :root design tokens and
 *     theme-agnostic primitives (.zen-card …) used by the wizard/dialogs.
 *   - Chrome partials are nested under `body.naruto-zen` (added by
 *     scripts/theme/main.mjs) so they beat PF1e's unlayered selectors and
 *     never leak into non-Naruto worlds.
 *   - Per-app partials are nested one level deeper under `.naruto-zen-target`
 *     (added by the render hooks in main.mjs).
 *
 * `@import` is required for the theme partials because `@use` cannot be nested
 * inside a selector. Each partial keeps its own `@use "colors"` for namespaced
 * Sass variables; `@font-face` in _fonts bubbles to the document root.
 */

@use "tokens";
@use "components/index";

body.naruto-zen {
    @import "theme/fonts";
    @import "theme/global";
    @import "theme/global-appv2";
    @import "theme/ui";
    @import "theme/nav";
    @import "theme/compatibility-modules";
    @import "theme/v13-chrome";
    @import "theme/pf1-surfaces";

    .naruto-zen-target {
        @import "theme/pf1-sheets";
        @import "theme/naruto-module";
        @import "theme/natures";
        @import "theme/disciplines";
        @import "theme/villages";
    }
}
```
